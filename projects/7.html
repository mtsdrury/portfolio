Fashion Image Classifier with W&B Experiment Tracking

Comparing transfer learning against from-scratch CNNs for fashion product classification

View Repository →
PyTorch torchvision Weights & Biases pytest GitHub Actions scikit-learn Pandas

The Problem

Evaluating whether transfer learning from ImageNet provides a meaningful improvement over training from scratch for fashion product classification. The Kaggle Fashion Product Images dataset contains 44,000 images across dozens of categories, but many classes have insufficient samples for robust training. Filtering to categories with at least 500 images and comparing three architectures provides a controlled experiment.

What Was Built

  • Dataset preparation filters the Kaggle CSV to top categories by count, verifies image existence on disk, and applies stratified train/val/test splits to maintain class proportions across splits.
  • Three models are implemented: SimpleCNN (3-block CNN trained from scratch), ResNet-50 (pretrained on ImageNet), and EfficientNet-B0 (pretrained on ImageNet), all with replaced classification heads.
  • Training loop in `training.py` accepts a `use_wandb` flag, allowing local development without API keys while enabling experiment tracking in production runs.
  • W&B integration is isolated in `wandb_utils.py`, keeping training and evaluation functions pure and testable without external dependencies.
  • Tests mock pretrained model backbones using `@patch` decorators to avoid downloading weights in CI, and use small random tensors to verify output shapes and architecture changes.
  • A `sweep.yaml` file defines a Bayesian hyperparameter search over learning rate, batch size, and dropout for each model architecture.

Outcome

The system provides a complete pipeline for training, evaluating, and comparing image classification models with full CI coverage. All 34 tests run in GitHub Actions using CPU-only PyTorch, avoiding large CUDA downloads. The codebase is structured for reproducibility, with separate notebooks for local experimentation and Colab execution.

Highlights

Testable W&B integration pattern
  • W&B calls are isolated in `wandb_utils.py` and accessed via a `use_wandb` flag in `train_model()`, allowing the training loop to execute locally without credentials.
  • Tests in `test_wandb_utils.py` mock the `wandb` module using `patch.dict(sys.modules)` to verify logging behavior without requiring an active W&B project.
  • This pattern enables local debugging and CI testing while preserving full experiment tracking in production runs.
Mocked pretrained weights in tests
  • `test_models.py` patches `torchvision.models.resnet50` and `efficientnet_b0` with tiny mock models that mimic the real backbone interfaces (`.fc` attribute for ResNet, `.classifier` for EfficientNet).
  • Each mock uses a simple linear layer to transform flattened input to 2048 or 1280 features, avoiding 100MB+ weight downloads in CI.
  • Tests verify that the classification head is correctly replaced with a custom `nn.Sequential` outputting the target number of classes.
Stratified splits with verification
  • `data_loader.py` uses `train_test_split` with `stratify=df['label']` to maintain proportional class representation across train, validation, and test sets.
  • A `verify_images_exist()` function filters the CSV to only include rows where the corresponding image file exists on disk, preventing runtime errors during training.
  • The pipeline reads from a Kaggle CSV, filters to categories with 500+ images, encodes string labels to integers, and builds PyTorch DataLoaders with configurable augmentation.
CI without CUDA dependencies
  • GitHub Actions CI runs all tests using CPU-only PyTorch, avoiding the 2GB CUDA toolkit download by installing from the CPU-only channel.
  • Tests use `torch.randn()` and `TensorDataset` to generate synthetic batches, keeping memory usage under 100MB.
  • `pyproject.toml` configures pytest and ruff for consistent test discovery and linting across local and CI environments.
