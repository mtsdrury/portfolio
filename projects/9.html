Fashion Reviews Analysis with PySpark

Distributed analysis of 2.5M Amazon Fashion reviews to identify helpfulness signals

View Repository →
PySpark MLlib Python HuggingFace Datasets Pytest GitHub Actions Matplotlib

The Problem

E-commerce platforms struggle to surface the most useful product reviews. Only 20% of Amazon Fashion reviews receive any helpful votes, and retailers need to understand what differentiates reviews that inform purchase decisions from those shoppers ignore. This project analyzes 2.5 million reviews to identify the structural and linguistic features that predict review helpfulness.

What Was Built

  • Built a sample-first development workflow where `USE_SAMPLE = True` in `config.py` loads 100K rows for rapid iteration, then switches to full 2.5M dataset for production runs
  • Automated data ingestion via HuggingFace Datasets library in `data_loader.py`, streaming directly to Parquet with no manual downloads
  • Implemented six distinct PySpark analyses in `analysis.py`, each showcasing different features: `groupBy`/`agg` for rating distributions, joins on `parent_asin` for price tier analysis, Window functions (`ntile`, `lag`) for temporal trends and quartile binning
  • Constructed feature engineering pipeline in `preprocessing.py` using `withColumn` and `when`/`otherwise` for text length binning, timestamp parsing with PySpark date functions, and price extraction via regex
  • Deployed dual APIs for each analysis: DataFrame transformations in Python and equivalent Spark SQL queries with CTEs, demonstrating both programming paradigms
  • Built MLlib pipelines in `text_pipeline.py` chaining Tokenizer, StopWordsRemover, CountVectorizer, and IDF for TF-IDF feature extraction, followed by VectorAssembler and LogisticRegression for binary classification
  • Validated all transformations with 25 pytest cases in `tests/`, mocking Spark DataFrames to ensure CI runs without Java dependencies
  • Rendered results in Jupyter notebook `analysis.ipynb` with matplotlib/seaborn plots saved to `results/figures/`

Outcome

The system processes 100K reviews in sample mode or scales to 2.5M for full analysis, demonstrating PySpark's distributed computation capabilities. Classification model achieves 63% AUC-ROC predicting review helpfulness. Complete test coverage and GitHub Actions CI ensure reproducibility. Analysis reveals that longer reviews (400+ chars) have 4x higher helpfulness rates than very short reviews, and photo reviews receive 2.6x more helpful votes despite being only 6% of the dataset.

Highlights

Dual API Design Pattern

Each analysis exposed through both PySpark DataFrame transformations and Spark SQL queries. For example, `rating_by_verified()` uses `.groupBy()` and `.agg()`, while `rating_by_verified_sql()` achieves identical results with `GROUP BY` and `CASE WHEN` in raw SQL. Registered DataFrames as temp views via `createOrReplaceTempView()` to enable seamless switching between paradigms within the same notebook.

Window Function Composition

Implemented price quartile binning via `Window.orderBy("price").rowsBetween(Window.unboundedPreceding, Window.unboundedFollowing)` with `ntile(4)` partitioning in `add_price_quartile()`. Temporal analysis in `temporal_trends_sql()` uses Window `lag()` for month-over-month comparison and `rowsBetween(-2, 0)` for 3-month rolling averages, both in a single CTE.

MLlib Pipeline Integration

Constructed reusable `build_tfidf_pipeline()` returning a fitted Pipeline of five transformers. Vocabulary size limited to top 5000 terms in CountVectorizer, IDF computed across entire corpus, then VectorAssembler merges TF-IDF features with numeric metadata (text_length, verified_purchase) for LogisticRegression input. Extracted top IDF terms by sorting vocabulary weights in `extract_top_tfidf_terms()`.

Production-Ready Testing Strategy

Pytest suite mocks small Spark DataFrames in `conftest.py` fixtures, enabling tests to run in GitHub Actions without Java installation. `test_text_pipeline.py` validates TF-IDF dimensions, `test_evaluation.py` verifies confusion matrix arithmetic, and `filterwarnings` in `pyproject.toml` suppresses PySpark deprecation noise. All 25 tests complete in under 10 seconds locally.

Results

Text Length Drives Helpfulness

Longer reviews have significantly higher helpfulness rates. Very short reviews (under 50 chars) see only 10% marked helpful, while extremely long reviews (600+ chars) reach 57% helpfulness. Average text length for helpful reviews is 279 chars versus 132 chars for unhelpful reviews.

Metrics: 6x helpfulness increase from very_short to extremely_long bins

Photo Reviews Outperform Text-Only

Reviews with attached photos achieve 46% helpfulness rate compared to 18% for text-only reviews, despite representing only 6% of the dataset (6,277 vs 93,723 reviews). Photo reviews also receive 2.8 average helpful votes versus 0.4 for text-only.

Metrics: 2.6x higher helpfulness rate, 7x more helpful votes on average

Negative Reviews Are Most Valued

One-star reviews have the highest helpfulness rate at 23%, compared to 18% for five-star reviews. Average helpful votes peak at 1-star (0.63 votes) and 4-star (0.61 votes), suggesting shoppers actively seek critical and balanced perspectives.

Metrics: 23% helpfulness rate for 1-star vs 18% for 5-star

Premium Products Generate More Engagement

Reviews for highest price quartile products (top 25% by price) show 25% helpfulness rate versus 19% for lowest quartile. Higher-priced items correlate with more detailed reviews and greater shopper investment in reading feedback.

Metrics: 25% helpfulness in Q4 price tier vs 19% in Q1

Review Volume Peaked in 2019

Monthly review counts grew from near zero in 2003 to a peak of 2,000+ reviews in August 2019, followed by decline through 2022. Customer satisfaction (average star rating) dropped from 4.1 in 2013-2016 to 3.7 in 2021-2022, suggesting either declining product quality or increased reviewer selectivity.

Metrics: Peak: 2,000 reviews/month (2019), Satisfaction drop: 4.1 to 3.7 stars (2013-2022)

Classification Model Performance

Logistic regression model trained on TF-IDF features plus numeric metadata achieves 79% accuracy, 63% AUC-ROC, and 32% AUC-PR on test set. High true negative rate (15,172 TN) but struggles with true positives (531 TP vs 3,407 FN), reflecting extreme class imbalance where only 20% of reviews are helpful.

Metrics: AUC-ROC: 0.626, Accuracy: 0.792, Precision: 0.740, F1: 0.746
