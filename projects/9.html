Job Tracker

Desktop job search manager backed by a single CSV file

View Repository →
Python tkinter ttkbootstrap PyInstaller

The Problem

Spreadsheets become difficult to maintain as job applications pile up. Tracking referral outreach, follow-up timing, and missing fields requires constant manual scanning. This tool provides structure around a CSV backend with dual interfaces: a GUI for quick edits during application sessions and a CLI for scripted updates and reports.

What Was Built

  • The data model is a flat CSV with 15 columns covering application metadata, referral contacts, and document tracking. All operations read the full file into memory, modify rows, and write back atomically.
  • The GUI uses a mixin architecture. `TrackerApp` composes `ListTabMixin`, `DetailTabMixin`, `SummaryTabMixin`, `ReferralsMixin`, `TemplatesMixin`, and `PopupsMixin`. Each mixin owns one aspect of the interface and shares state through the base class.
  • The list tab renders jobs in a treeview with color-coded status tags and strikethrough styling for rejected or withdrawn entries. Filters operate on status, referral stage, or substring matches across company, role, and referral names.
  • The detail tab uses a scrollable canvas holding labeled entry widgets for each column. Saving writes changes back to the CSV and refreshes the list view. A file browser button auto-populates the cover letter path field.
  • Referral management separates name, LinkedIn URL, connection, and status into semicolon-delimited parallel lists. A popup form validates inputs and appends to all four columns simultaneously.
  • The summary tab aggregates status counts, referral hit rates, and recent activity (applications this week/month). A visual bar chart renders status distribution using canvas rectangles scaled to row counts.
  • The CLI exposes `add`, `update`, `list`, `summary`, `report`, and `remove` commands. The `report` command auto-generates action items: stale applications (21+ days without status change), un-messaged referrals, and large "Not Yet Applied" backlogs.
  • URL parsing in the "New Job" popup extracts company, role, and location from schema.org JSON-LD when present, reducing manual entry for common job boards.
  • PyInstaller bundles the GUI into a single Windows executable with no external dependencies. The build script copies the output to the repo root for distribution.

Outcome

The application ships as a 12MB standalone executable requiring no Python installation. The GUI stays open during application sessions, supporting rapid entry and filtering across multiple jobs. The CSV format ensures compatibility with spreadsheet tools and version control.

Highlights

Mixin-based GUI composition

The main `TrackerApp` class inherits from six mixins, each handling one tab or feature. Mixins share state through `self.rows`, `self.csv_path`, and `self.selected_idx`, avoiding tight coupling between tabs. This pattern keeps each feature isolated in its own module while preserving access to shared application state.

Parallel list encoding for referrals

Referral data (names, LinkedIn URLs, connections, statuses) is stored as four semicolon-delimited strings in separate columns. The `ReferralsMixin` splits these on read, validates parallel list lengths, and re-joins on write. This flattens a one-to-many relationship into CSV without introducing JSON blobs or external tables.

Auto-generated action items in reports

The `report` command scans for stale applications (21+ days in "Applied" status), referrals marked but not messaged, and jobs stuck in "Not Yet Applied". Each condition triggers a specific action item with counts and filtering instructions. This turns passive data into concrete next steps.

Schema.org extraction for job postings

The new job popup attempts to parse schema.org JobPosting JSON-LD from pasted URLs. If found, it auto-fills company name (`hiringOrganization.name`), role (`title`), and location (`jobLocation.address.addressLocality`). This reduces transcription errors and speeds up entry for common job boards.
