The Problem

Developers need polished portfolio entries for personal websites, but writing them manually from code is tedious and inconsistent. Extracting meaningful technical narratives from repositories requires understanding architecture, ownership context, and what makes a project interesting to showcase.

What Was Built

  • OAuth flow authenticates users and fetches their GitHub repositories
  • Analysis pipeline clones repos, samples files strategically, and detects tech stack from dependencies and extensions
  • Ownership calculator determines contribution level by analyzing commit authorship and fork status
  • Structure analyzer builds directory trees and counts LOC across file types
  • Claude API receives context (ownership, structure, file samples) with a structured prompt tuned for third-person portfolio writing
  • Background tasks handle long-running analyses without blocking requests
  • Database tracks analysis status with granular progress states (cloning, analyzing, generating)
  • Export service renders results to Markdown or standalone HTML using Jinja2 templates
  • Rate limiting prevents abuse by tracking analysis requests per user and mode

Outcome

The system produces ready-to-use portfolio entries with problem statements, architecture descriptions, and technical highlights. Both quick and deep analysis modes are supported. Users can export to Markdown for static sites or HTML for immediate use.

Highlights

Multi-stage analysis pipeline

The pipeline in `analysis/pipeline.py` orchestrates five distinct phases with status updates at each step. File sampling uses a tiered strategy (always include root configs, sample subdirectories proportionally) to stay within token limits while preserving project structure. Tech detection combines dependency parsing with file extension heuristics to build a complete stack profile.

Structured LLM prompting

The prompt in `analysis/prompts.py` constrains Claude to output valid JSON matching a Pydantic schema. Token budget enforcement and explicit voice guidelines (third person, no em dashes, bullet points for structure) ensure consistent formatting. The prompt includes ownership context so generated entries reflect actual contribution level.

Async session-based auth

Authentication uses FastAPI's SessionMiddleware with CSRF tokens for form submissions. Dependencies in `auth/dependencies.py` check session state and return the current user or redirect to login. GitHub tokens are encrypted at rest using `cryptography.fernet` before storage in the database.

Progressive web interface

HTMX partials handle paginated repository lists and live analysis progress polling without full page reloads. The template in `web/templates/analyze.html` conditionally renders progress bars during processing or the full portfolio result when complete. Search and pagination use server-side rendering with clean URL query params.
